Tokens

Design: a background poller aggregates per-CLI usage into ~/.usage/polish/; the prompt reads that JSON only and never parses logs. Without the cache, polish tokens says no token data yet (run: polish-tokens-collect).

Collector

polish-tokens-collect          # tail logs, update ~/.usage/polish/*.json
polish-tokens-collect --help   # usage (also: -h)

Sources (all under $HOME unless overridden):

  • claude — ~/.claude/projects/**/*.jsonl, message.usage, deduped per message id
  • muse — ~/.local/share/muse/sessions/**/session.jsonl, model_completed events only
  • opencode — ~/.local/share/opencode/opencode.db, message rows read-only (the part table is never read; no WAL/SHM/journal files are created)
  • pi — ~/.pi/agent/sessions/**/*.jsonl, assistant message.usage (auth.json is never touched)
  • codex — ${CODEX_HOME:-~/.codex}/sessions/**, best-effort usage shapes; skipped silently when not installed

Outputs in ${POLISH_USAGE_DIR:-~/.usage/polish}: daily.json (date, total_tokens, total_cost_usd, by_cli, prompt), per-CLI <cli>.json files (daily totals plus per-model breakdown, unknown_lines, deduped_lines), and cursors.json (per-file size/mtime/offset, so re-runs are incremental; daily.json is rebuilt from today's per-CLI docs and resets on a new day). Env overrides: POLISH_USAGE_DIR, POLISH_PRICES_FILE, POLISH_PRICES_OVERRIDE, POLISH_TODAY (YYYY-MM-DD), CODEX_HOME.

Scheduling

Run the collector every 60–300s. The installer ships a systemd user timer for this — pass --timer at install time (installer/polish-tokens.{service,timer}, every 2 minutes). Without systemd, use cron: */2 * * * * polish-tokens-collect.

First run imports existing history into today's totals (later runs are incremental via cursors.json), so day one legitimately shows lifetime-to-date numbers; subsequent days are true deltas.

Prices

Rates live in the versioned map lib/prices.json (USD per 1M tokens; estimates only). Lookup tries the exact model name, then strips trailing -segments, then strips a provider/ prefix, then falls back to default. Override entries without editing that file via ~/.usage/polish/prices.override.json (same shape, deep-merged over the base; or point POLISH_PRICES_OVERRIDE elsewhere). Pi/opencode lines that carry a reported cost use it directly.

Viewing

polish tokens          # same as: polish tokens status
polish tokens status   # pretty day table (CLI / TOKENS / COST + TOTAL)
polish tokens --prompt # cached prompt string only, e.g. "$1.23 | 45K tok"

The status table merges per-CLI files for any CLI missing from daily.json, and needs python3. Shell helpers (polish-tokens plugin): pt prints daily.json (polish_tokens_today); cx prints a context burn gauge like ctx 12% (24,567/200,000) (polish_context_pct). cx prefers explicit context_tokens/context_window fields when present — the collector does not write them yet (roadmap) — and otherwise divides day cumulative total_tokens by POLISH_CONTEXT_WINDOW (default 200000), so it is a burn-rate gauge, not live context pressure.

Prompt modules

The Starship preset (starship.toml) adds polish_tokens (polish tokens --prompt), polish_context (one JSON read computing a N% from the same cache), and polish_agent (see Agents). Unknown flags error, e.g. polish tokens bogus prints usage and exits 1.
